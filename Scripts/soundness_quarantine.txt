# Exact-count soundness quarantine ledger.
#
# Format:
# <kind> <YYYY-MM-DD> <tracking-ref> <reason containing count=N>
#
# A quarantined kind is a ratchet, not an unlimited allowance: the scanner
# fails above count=N, warns at the exact baseline, and warns below it so this
# ledger is reduced with the next fix.
#
# A kind with NO row is not unprotected: any count > 0 fails the scan as
# "is not quarantined". A row pinned at count=0 is therefore equivalent to
# no row at all, and a burned-down class should lose its row rather than
# keep a zero one (2026-08-28: action-dispatch-miss and
# handler-resolution-gesture both did).
#
# Enforcement is asymmetric, so a green gate proves only count <= N -- NOT that
# N is current. A baseline left too high after a fix merely warns, and that is
# not hypothetical: through 2026-07-30 registration-publication measured 1122
# against a 1194 baseline, 72 too high, and the gate printed "is below baseline;
# reduce the ledger" inside every passing run for weeks without anyone acting on
# it. Every row below currently sits EXACTLY on its baseline; if one starts
# printing "is below baseline", reduce it with the next change that touches
# that area rather than letting the slack accumulate.
#
# See "Quarantined residuals" in docs/SOUNDNESS-ORACLES.md for each row's
# provenance, what its residual actually is, its burn-down expectation, and its
# reconciliation against the Program-5-S0 findings census (whose published
# figures are pre-S1).

# 1. registration-publication 1199 -> 64. `RuntimeRegistrationSet`'s member
#    registries are OPTIONAL, and the F04 oracle built its comparison scratch
#    with `RuntimeRegistrationSet.scratch()`, which always constructs all
#    fifteen. A host installs the registries it needs, and a bare
#    `ResolveContext` -- every `DefaultRenderer` stress render -- installs
#    none, so the oracle compared an EMPTY live target against a fully
#    populated rebuild and reported every registration in the graph as
#    `live=0 rebuilt=1`. Publishing into a registry the target does not have
#    is a no-op by construction; no scoped restore was ever at fault. The
#    scratch now mirrors the target's membership
#    (`RuntimeRegistrationSet.scratch(mirroringMembershipOf:)`), pinned by
#    `RuntimeRegistrationRestoreScopingTests.sparseLiveTargetDoesNotTripPublicationOracle`.
#    What survives is entirely the OPPOSITE arm, and it is a real defect: a
#    scoped removal that fails to clear an entry, leaving 58 stacked
#    duplicates (`live=2 rebuilt=1` on key+paste pairs and a ScrollView key
#    trio) and 6 stale survivors of a departed node (`live=1 rebuilt=0`).
#    The removal matches registration-KEY identity prefixes while the
#    restore selects by NODE identity; a control registering outside the
#    removal cover keeps its old entry and the restore adds a second.
#
# 2. teardown-coherence-leak 499 -> 174. The graph lane's entire
#    contribution (325) was `RuntimeRegistrationRestoreScopingTests`' generated
#    seam cases: they seed capture-island nodes (Portal/Overlay/LazyTab/
#    SheetCaptured/LazyViewport/IdentityReroot) that are deliberately committed

#    anchor that production's resolve-lifetime scope records for exactly that
#    shape. The islands landed with `anchors=[]` and the finalize-barrier
#    census correctly called every one of them unreachable. The fixture now
#    anchors them to their declaring sibling host. The census was right; the
#    fixture was unfaithful. What survives is the runtime lane's genuine F91
#    residual (List/lazy content strands whose `ID[i]` host carries no anchor,
