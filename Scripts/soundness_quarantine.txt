# Exact-count soundness quarantine ledger.
#
# Format:
# <kind> <YYYY-MM-DD> <tracking-ref> <reason containing count=N>
#
# A quarantined kind is a ratchet, not an unlimited allowance: the scanner
# fails above count=N, warns at the exact baseline, and warns below it so this
# ledger is reduced with the next fix.
#
# A kind with NO row is not unprotected: any count > 0 fails the scan as
# "is not quarantined". A row pinned at count=0 is therefore equivalent to
# no row at all, and a burned-down class should lose its row rather than
# keep a zero one (2026-08-28: action-dispatch-miss and
# handler-resolution-gesture both did).
#
# Enforcement is asymmetric, so a green gate proves only count <= N -- NOT that
# N is current. A baseline left too high after a fix merely warns, and that is
# not hypothetical: through 2026-07-30 registration-publication measured 1122
# against a 1194 baseline, 72 too high, and the gate printed "is below baseline;
# reduce the ledger" inside every passing run for weeks without anyone acting on
# it. There are NO rows below as of 2026-08-29: every kind is enforced at plain
# T-fail. If a row is ever added again and starts printing "is below baseline",
# reduce it with the next change that touches that area rather than letting the
# slack accumulate.
#
# See "Quarantined residuals" in docs/SOUNDNESS-ORACLES.md for the provenance
# of every row this ledger has carried, what each residual actually was, and the
# reconciliation against the Program-5-S0 findings census (whose published
# figures are pre-S1).
